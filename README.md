# ПОС — преподавательская оценка студентов

Консольная ведомость одного курса на Python 3.9+. Студенты, рубрикатор и выставленные оценки живут в памяти до выхода из программы. CSV сохраняет снимок итогов на диске. Для сборки приложения используется библиотека `dependency-injector`.

## Запуск и тесты

Откройте терминал в каталоге с этим README. При первом запуске создайте виртуальное окружение и установите зависимости.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Запустите ведомость из этого окружения.

```sh
.venv/bin/python -m pos
```

Все тесты запускаются из того же каталога.

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Среди проверок есть сквозной тест `tests/test_cli.py`. Он запускает консоль, вводит команды и читает созданные CSV-файлы до и после отмены оценки.

## Правила ведомости

- **Что считается одной оценкой?** У студента по каждому критерию есть одна действующая оценка. Повторная запись исправляет её. Отмена возвращает критерий в состояние «пока нет оценки».
- **Какие числа допустимы?** Максимум критерия — положительное целое число. Балл — целое от нуля до максимума включительно. Вес положительный и может быть дробным. Сумма весов может отличаться от единицы.
- **Как посчитать процент?** Для каждого учтённого критерия берём долю выполнения (балл / максимум), умножаем её на вес, складываем произведения и делим на сумму учтённых весов. Результат умножаем на 100. Например, за проект 8/10 с весом 3 и за защиту 3/5 с весом 1 дают `100 × (0,8 × 3 + 0,6 × 1) / 4 = 75%`.
- **Как обработать пропуск?** Итог курса учитывает все критерии. Пропуск даёт нулевой вклад. Текущий результат учитывает только критерии с выставленной оценкой, включая выставленный ноль. Если сумма учтённых весов равна нулю, результат отсутствует. В CSV ему соответствует пустое поле.
- **Когда округлять?** Расчёт использует точные дроби. Меню и экспорт округляют только при выводе до двух знаков после запятой.

## Карта DDD

Словарь модели совпадает с языком преподавателя. `Student` — студент, `Criterion` — критерий, `Rubric` — рубрикатор, `Evaluation` — оценка, `GradebookEntry` — ведомость студента.

- **Сущности.** Равенство и хеш `Student` определяет ID. Объект с уточнённым именем и прежним ID представляет того же студента. У однофамильцев с разными ID отдельные ведомости. Для поиска критерия внутри рубрикатора используется ID критерия.
- **Объект-значение.** Оценка определяется критерием и баллом. Ведомость заменяет объект целиком при исправлении. У оценки нет отдельного ID и истории версий.
- **Границы агрегатов.** Рубрикатор управляет набором критериев и уникальностью их ID. Ведомость управляет оценками одного студента и получает ссылку на рубрикатор курса при создании. Каждый добавленный в курс критерий сразу виден во всех его ведомостях. Максимум и вес уже добавленного критерия неизменяемы.
- **Инварианты.** Рубрикатор находит критерий по ID и создаёт оценку, которая проверяет диапазон. Ведомость записывает результат только после успешной проверки.
- **Repository.** Приложение обращается к ведомостям через порт `GradebookRepository`. Адаптер `MemoryGradebooks` хранит их по ID студента.
- **Domain Service.** `FinalScoreCalculator.calculate(entry)` запрашивает у ведомости пары «критерий, балл или пропуск». Максимум при проверке балла и при расчёте процента берётся из одного рубрикатора. Тест `test_each_entry_uses_its_own_rubric_for_grading_and_totals` проверяет две ведомости с одним ID критерия и разными максимумами.

## Обоснование выбора паттернов GoF

### Порождающий паттерн — простая фабрика оценок

**Где применяется.** В `GradebookEntry.set_score` ведомость вызывает `Rubric.create_evaluation`. Рубрикатор находит критерий по ID, а конструктор `Evaluation` проверяет балл по максимуму этого критерия. [Доменная модель](pos/domain.py)

**Зачем.** Первое выставление и исправление балла проходят одну и ту же проверку. Если преподаватель пытается исправить 8/10 на 12/10, фабрика передаёт ошибку в ведомость до замены оценки, и у студента остаётся 8/10. Выбрана простая доменная фабрика, поскольку в ведомости один тип оценки — `Evaluation`.

### Структурный паттерн — Facade (фасад)

**Где применяется.** Пункт меню «Выставить / исправить оценку» вызывает `AssessmentFacade.set_score`. Фасад получает ведомость из репозитория, передаёт ей команду и сохраняет ведомость после успешного изменения. [Меню](pos/cli.py) · [Фасад](pos/application.py)

**Зачем.** Меню передаёт ID студента, ID критерия и балл одним вызовом. Порядок работы с репозиторием задан в одном месте, поэтому изменение способа хранения ведомостей не требует правок в меню.

### Поведенческий паттерн — Strategy (стратегия)

**Где применяется.** `FinalScoreCalculator` обращается к стратегии через `ScoringPolicy.include`. Стратегия `CourseTotal` включает все критерии, а `CurrentResult` — только критерии с выставленным баллом, включая ноль. [Стратегии и калькулятор](pos/domain.py)

**Зачем.** Преподавателю нужны два результата по одним оценкам. Если за проект с весом 3 студент получил 8/10, а защита с весом 1 ещё не оценена, итог курса равен 60%, текущий результат — 80%. Обе стратегии используют одну формулу в калькуляторе и задают только правило учёта пропуска.

## Принципы SOLID

| Принцип | Где проявляется |
| --- | --- |
| S | Правила баллов находятся в домене, чтение команд в CLI, запись CSV в адаптере. |
| O | Новый критерий добавляется как данные. Новая политика включения критериев подключается к тому же калькулятору. |
| L | Обе стратегии принимают балл или пропуск и отвечают, включать ли критерий. Калькулятор одинаково вызывает каждую из них. |
| I | Хранение ведомостей и выгрузка итогов имеют отдельные порты. Для чтения и записи одной ведомости оставлен общий репозиторий из четырёх методов, поскольку фасад использует обе операции. |
| D | Фасад принимает порты репозитория и экспортёра через конструктор. Небольшой DI-контейнер собирает зависимости при запуске и передаёт готовый фасад меню. |

## Как DI-контейнер собирает ведомость

В `pos/container.py` зарегистрированы правила создания объектов. В точке входа вызов `container.assessments()` запрашивает фасад. Контейнер создаёт его зависимости и передаёт их в конструктор.

- `Singleton` создаёт один рубрикатор и один репозиторий на экземпляр контейнера. Все фасады одного сеанса видят одних студентов, критерии и оценки.
- `Factory` создаёт фасад, калькуляторы со своими стратегиями и CSV-экспортёр по запросу. Домен работает с полученными объектами. При создании другого контейнера начинается отдельный сеанс с пустой ведомостью.
